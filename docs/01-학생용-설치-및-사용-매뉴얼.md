## 0단계. GitHub에서 `subway` 브랜치 받기 & Antigravity 시작

### 0-1. 저장소 받기 (팀원 각자 실행)
PowerShell 콘솔을 열고, 1차 완성본이 들어있는 `subway` 브랜치를 지정하여 클론합니다:
```powershell
git clone -b subway https://github.com/foxjini/agent-vibe-coding-starter-kit2.git iot-subway-system
cd iot-subway-system
```
> 💡 Git 다운로드가 어렵다면, GitHub 브랜치 선택 메뉴에서 `subway`를 고른 뒤 **Code → Download ZIP**을 눌러 내려받아 압축을 풀어도 됩니다.

### 0-2. 프로젝트 구조 확인
폴더 내에 아래 구성 요소들이 모두 포함되어 있는지 확인합니다:
- `AGENTS.md`: 지하철 프로젝트 정의서 (혼잡도 LED, 컨베이어 모터, 카메라, 압력센서 등)
- `.agents/`: AI 에이전트 하네스 (rules, skills, workflows — 이미 완성됨)
- `docs/`: 2차 개발 매뉴얼 및 연동 부록
- `backend/`: FastAPI 백엔드, DB 스키마(`db/init.sql`), WebSocket 매니저
- `frontend/`: Next.js 지하철 객차 혼잡도 및 좌석 모니터링 대시보드
- `vision/`: Native OpenCV DNN 및 경량 ONNX 모델(`yolov8n.onnx`)이 탑재된 영상인식 클라이언트
- `pi/`: 라즈베리파이 5 하드웨어 데몬 (4단계에서 연동)

### 0-3. Antigravity IDE 열기 & Rules 설정
Antigravity IDE에서 방금 내려받은 `iot-subway-system` 폴더를 워크스페이스로 엽니다.

**⚠️ Rules는 3개만 "Always On"으로 설정하세요.**  
상단 "…" 메뉴 → **Customizations** 패널 → **Rules**에서 아래 3개만 **Always On**으로 켭니다:
- `karpathy-principles` (모든 작업의 대원칙: 단순함, 외과적 변경)
- `security-rules` (시크릿 보호)
- `coding-standards` (코딩 스타일 표준)

> 💡 나머지 규칙(`api-rules`, `db-rules`, `hardware-rules`, `vision-rules` 등)은 AI 에이전트 호출 시 자동으로 로드되므로 항상 켜둘 필요가 없습니다 (Gemini 무료 티어 토큰 절약).

## 1단계. 환경변수(.env) 및 각 파트 환경 준비 (학생 직접 실행)

### 1-1. 환경변수 파일(.env) 생성
프로젝트 루트에서 각 폴더의 `.env.example`을 복사하여 `.env`를 만듭니다:
```powershell
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
copy vision\.env.example vision\.env
copy pi\.env.example pi\.env
```
> 🔒 **보안 및 인증 주의**: `backend/.env`, `vision/.env`, `pi/.env`의 `DEVICE_API_KEY`는 서로 같은 값을 가져야 디바이스 인증이 통과됩니다. 팀 고유의 문자열(예: `subway_secure_key_9876`)을 정해 세 파일에 동일하게 지정하세요.

### 1-2. 데이터베이스(MariaDB) 준비 및 초기화
1. XAMPP Control Panel을 열고 **MySQL (MariaDB)**을 **Start**합니다.
2. PowerShell(또는 phpMyAdmin 웹 SQL 탭)에서 `backend/db/init.sql`을 실행하여 DB와 지하철 디바이스 시드 데이터를 생성합니다:
```powershell
# 프로젝트 루트에서 실행 (mysql이 환경변수 PATH에 등록되어 있는 경우)
Get-Content backend\db\init.sql | mysql -u root
```
> 💡 `mysql` 명령어가 실행되지 않는다면, 브라우저에서 `http://localhost/phpmyadmin`에 접속한 뒤 상단 **SQL 탭**을 누르고 `backend/db/init.sql` 파일 내용을 그대로 붙여넣어 실행하세요.

### 1-3. 백엔드(FastAPI) 가상환경 설정
```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```

### 1-4. 프론트엔드(Next.js) 패키지 설치
Next.js 앱과 지하철 UI 컴포넌트가 이미 구축되어 있으므로 패키지만 설치합니다:
```powershell
cd frontend
npm install
cd ..
```

### 1-5. 비전(OpenCV DNN) 가상환경 설정
> 🚀 **초경량 OpenCV DNN 엔진**: PyTorch 수 GB 다운로드 없이 약 50MB 의존성으로 고속 CPU 추론이 가능합니다.
```powershell
cd vision
# Python 3.12 지정 생성 권장 (Windows 파이썬 런처)
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```

## 2단계. 1차 완성 지하철 시스템 로컬 구동 점검 (3개 멀티 터미널)

IoT 실시간 시스템은 여러 독립 프로세스가 상호작용합니다. **터미널을 3개 열어 각각 실행 상태를 유지**합니다.

```
┌───────────────────────────────┐   WebSocket / REST    ┌───────────────────────────────┐
│     터미널 1: 백엔드 (8000)     │ ◄───────────────────► │   터미널 2: 프론트엔드 (3000)   │
│ (FastAPI, MariaDB, 상태 중계) │                       │ (Next.js 지하철 실시간 대시보드) │
└───────────────────────────────┘                       └───────────────────────────────┘
                 ▲
                 │ POST /api/v1/vision/events
┌───────────────────────────────┐
│     터미널 3: 비전 클라이언트    │
│ (OpenCV DNN 웹캠 / 가상 시뮬)  │
└───────────────────────────────┘
```

### 2-1. [터미널 1] 백엔드 서버 실행
```powershell
cd backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```
- **확인**: 브라우저에서 `http://localhost:8000/docs`(Swagger API 문서) 및 `http://localhost:8000/health` 접속 시 정상 응답 확인.

### 2-2. [터미널 2] 프론트엔드 대시보드 실행
새 터미널 창을 열고 프론트엔드를 실행합니다:
```powershell
cd frontend
npm run dev
```
- **확인**: 브라우저에서 `http://localhost:3000`에 접속합니다.
  - 상단 연결 배지에 **"● 실시간 연결됨"**이 녹색으로 점등되는지 확인합니다.
  - 지하철 객차 시각화 뷰(여유/보통/혼잡 표시)와 임산부석 모니터링 카드가 렌더링되는지 확인합니다.

### 2-3. [터미널 3] 비전 인식 클라이언트 실행
새 터미널 창을 열고 비전 프로그램을 실행합니다:
> ⚠️ 사전에 Zoom, Teams, 웹 브라우저 화상채팅 등 웹캠을 사용하는 다른 앱을 모두 종료하세요.
```powershell
cd vision
.\venv\Scripts\Activate.ps1
python main.py
```
- **확인**:
  - 웹캠 창이 뜨고 실시간으로 승객(사람) 인원수가 카운트되는지 확인합니다.
  - 콘솔에 백엔드로 이벤트(`POST /api/v1/vision/events`)가 전송되는 로그가 출력되는지 확인합니다.
  - 웹캠이 연결되어 있지 않아도 가상 시뮬레이션 모드가 자동 동작하여 이벤트가 전송됩니다.

### 2-4. 1차 연동 결과 최종 점검
- 웹캠 앞에서 사람이 늘어나거나 줄어들 때, 프론트엔드 대시보드(`http://localhost:3000`)의 **혼잡도 단계(여유 → 보통 → 혼잡)와 LED 상태 색상이 실시간으로 자동 갱신**되는지 확인합니다.
- 대시보드 상에서 임산부석 압력센서 테스트 버튼을 눌러 점유 상태(사용 중/비어 있음)가 실시간 반영되는지 확인합니다.

## 3단계. 2차 고도화 개발 (AI 협업 & 03 핸드북 활용)

1차 시스템이 정상 구동됨을 확인했다면, 이제 본격적인 **2차 고도화 작업**에 착수합니다.  
세부 가이드와 프롬프트는 **`docs/03-2차완성-AI-개발-핸드북.md`**를 참조하여 진행합니다.

### 3-1. 주요 2차 고도화 개발 과제 예시
1. **혼잡도 분석 알고리즘 세분화**:
   - 승객 수에 따른 혼잡도 단계 임계값 미세 조정
   - 시간대별/구간별 객차 혼잡도 추이 그래프 컴포넌트 추가
2. **임산부석 모니터링 기능 고도화**:
   - 압력센서 착석 유지 시간 누적 측정 및 타이머 표시
   - 장기 점유 시 주의 안내 트리거 규칙 구현
3. **지하철 배경 모터(컨베이어) 연동**:
   - 열차 운행/정차 상태에 따른 모터 구동 및 정지 제어 로직 보강
4. **대시보드 UI/UX 향상**:
   - 반응형 레이아웃 개선, 알림 토스트, 통계 모달 창 구현

### 3-2. AI와의 효과적인 협업 팁
새로운 기능을 구현할 때는 Antigravity 채팅창에서 관련 역할을 명시하고 기존 규칙을 참고하게 합니다:
```
너는 이 프로젝트의 frontend-agent다. .agents/rules/ui-ux-rules.md를 따른다.
지하철 대시보드에 최근 10분간의 혼잡도 변화 추이를 보여주는 실시간 차트 컴포넌트를 추가해줘.
```
```
너는 이 프로젝트의 backend-agent다. .agents/rules/api-rules.md를 따른다.
임산부석 착석 시간이 5분을 초과할 경우 안내 경보 이벤트를 트리거하는 백그라운드 로직을 추가해줘.
```

## 4단계. 하드웨어 마이그레이션 (Mock → 라즈베리파이 5)

지하철 시스템을 실제 하드웨어(라즈베리파이 5, 혼잡도 표시 3색 삼색등 LED, 컨베이어 모터, 압력센서)에 연결합니다.  
상세한 REST 규격 및 협업 계약은 **`docs/부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md`**를 반드시 참고하세요.

### 4-1. 하드웨어 Provider 전환 (백엔드 담당)
`backend/.env`를 열고 디바이스 모드를 하드웨어로 변경합니다:
```
DEVICE_MODE=hardware
```

### 4-2. 라즈베리파이 5 데몬 설정 (라즈베리파이 담당)
라즈베리파이 5 터미널에 접속하여 데몬 환경을 준비합니다 (RP1 칩 제어를 위해 `lgpio` 필수):
> 💡 **중요**: PyPI에서 `pip install lgpio` 실행 시 C 컴파일 에러가 발생하므로, 라즈베리파이 OS 기본 APT 패키지를 설치한 후 `--system-site-packages` 옵션으로 가상환경을 생성합니다.

```bash
# 1. 시스템 APT 패키지 설치 (PyPI 컴파일 에러 방지)
sudo apt update && sudo apt install -y python3-gpiozero python3-lgpio

# 2. 가상환경 생성 (시스템 패키지 상속)
cd pi
python3 -m venv --system-site-packages venv
source venv/bin/activate

# 3. 경량 Python 패키지 설치
pip install -r requirements.txt

# 4. 하드웨어 배선 및 GPIO 1분 자가진단
python test_hardware_gpio.py
```

### 4-3. 백엔드 IP 연결 및 실행
Windows PC에서 `ipconfig` 명령으로 IPv4 주소(예: `192.168.0.25`)를 확인한 뒤, `pi/.env` 파일의 `BACKEND_URL`을 수정합니다:
```
BACKEND_URL=http://192.168.0.25:8000
DEVICE_API_KEY=subway_secure_key_9876
```

라즈베리파이에서 데몬을 실행합니다:
```bash
python main.py
```
> ⚠️ **안전 주의**: 하드웨어 배선은 반드시 전원을 끈 상태에서 교사 입회 하에 연결합니다.

## 5단계. 클라우드 배포

완성된 시스템을 로컬 환경을 넘어 클라우드에 배포하여 언제 어디서나 접속할 수 있도록 합니다.

1. **Supabase (PostgreSQL)**:
   - Supabase 프로젝트 생성 후, `.agents/skills/db-migration/SKILL.md`를 참고하여 MariaDB 스키마를 마이그레이션합니다.
2. **Render (FastAPI 백엔드)**:
   - GitHub 저장소를 연결하여 FastAPI 웹 서비스를 생성하고 환경변수를 설정합니다.
3. **Vercel (Next.js 프론트엔드)**:
   - Vercel에 프론트엔드를 배포하고 `NEXT_PUBLIC_API_BASE_URL`을 Render 백엔드 주소로 지정합니다.

## 트러블슈팅 FAQ

| 현상 / 에러 메시지 | 해결 방법 |
|---|---|
| `ModuleNotFoundError: No module named 'backend'` | `cd backend` 경로로 이동한 뒤 `uvicorn main:app`을 실행합니다. |
| MariaDB 접속 오류 / `No database selected` | XAMPP에서 MySQL이 Start 상태인지 확인하고, `init.sql`의 `USE smart_subway;` 구문이 정상 실행되었는지 확인합니다. |
| 대시보드 상단 배지에 "● 연결 대기 중" 표시 | 터미널 1의 백엔드 서버(`uvicorn main:app --reload --port 8000`)가 구동 중인지 확인합니다. |
| 웹캠 창이 뜨지 않거나 검은 화면 출력 | 웹캠을 사용 중인 다른 프로그램(Zoom, Teams, 브라우저 화상회의 등)을 작업 관리자에서 완전히 종료합니다. |
