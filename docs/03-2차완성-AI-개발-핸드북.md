## 2. 1차 완성 시스템 동작 확인 방법

IoT 시스템은 3개 프로세스가 실시간으로 통신합니다.

| 터미널 | 실행 위치 | 실행 명령어 | 역할 |
|---|---|---|---|
| **터미널 1** | `backend/` | `uvicorn main:app --reload --port 8000` | REST API 및 WebSocket 허브 (`http://localhost:8000/docs`) |
| **터미널 2** | `frontend/` | `npm run dev` | 관제 대시보드 UI (`http://localhost:3000`) |
| **터미널 3** | `vision/` | `python main.py` | 웹캠 실시간 사람 감지 및 백엔드 이벤트 전송 |

## 3. 핵심 통신 규약 & API 명세

### 1) 인증 규약 (`api-rules.md`)
- **사용자향 API (대시보드)**: 브라우저 세션 / 추후 Supabase JWT
- **디바이스향 API (라즈베리파이, Vision)**: `X-Device-Api-Key` 헤더 검증 (현재 키: `SUBWAY_2026_09_05_v1_0_0`)

### 2) 주요 REST 엔드포인트 (`backend/iot/router.py`)

| Method | Endpoint | 설명 | 인증 필요 여부 |
|---|---|---|---|
| `GET` | `/api/v1/devices` | 등록된 전체 디바이스 목록 및 최신 상태 조회 | X |
| `GET` | `/api/v1/devices/{id}` | 특정 디바이스 상세 상태 조회 | X |
| `POST` | `/api/v1/devices/{id}/control` | 사용자 액추에이터 제어 (`desired_state`, `desired_value`) | X |
| `GET` | `/api/v1/devices/{id}/desired-state` | **[HW용]** 라즈베리파이가 목표 상태를 조회(폴링) | X |
| `POST` | `/api/v1/devices/{id}/state` | **[HW용]** 라즈베리파이가 실제 반영된 현재 상태 보고 | `X-Device-Api-Key` |
| `POST` | `/api/v1/devices/sensor/pressure-simulate` | 임산부석 압력센서 착석/기립 시뮬레이션 | X |
| `POST` | `/api/v1/vision/events` | YOLO 영상인식 인원수 보고 및 혼잡도 트리거 실행 | `X-Device-Api-Key` |
| `GET` | `/api/v1/vision/events` | 최근 비전 감지 이벤트 목록 (최신 20건) | X |
| `GET` | `/api/v1/train/status` | 열차 1호차/2호차 종합 관제 정보 조회 | X |

### 3) WebSocket 실시간 스트리밍 (`ws://localhost:8000/ws`)
- 클라이언트 연결 즉시 `initial_state` 페이로드로 전체 디바이스 상태 전송
- 디바이스 상태 변경, 임산부석 착석/기립, 비전 감지 이벤트 발생 시 즉시 JSON 브로드캐스트:
  - `type`: `"device_updated"` | `"vision_event"` | `"pressure_seat_updated"`

## 4. 새 디바이스 추가 방법 (센서 / 액추에이터 확장)

새로운 부품(예: 비상벨 버튼, 실내 공기질 센서, 도어 개폐 장치 등)을 추가할 때는 아래 **4단계 순서**를 따릅니다.

   ```sql

   ON DUPLICATE KEY UPDATE name = VALUES(name), kind = VALUES(kind);
   ```

2. **Mock Provider 상태 등록 (`backend/iot/mock_provider.py`)**:
   - `self._devices["door_1"] = {...}` 초기 상태 추가
3. **Pydantic 스키마 정의 (`backend/schemas/device.py`)**:
   - 필요 시 상세 제어 필드 추가
4. **대시보드 UI 연동 (`frontend/app/page.tsx`)**:
   - 액추에이터면 `ActuatorCard`, 센서면 `SensorCard`로 바인딩

## 5. 라즈베리파이 5 마이그레이션 (2차 완성 핵심)

라즈베리파이 5 실기기를 연결할 때는 **백엔드 코드를 갈아엎지 않고 Provider만 교체**합니다.

```
┌─────────────────────────────────┐                 ┌─────────────────────────────────┐
│     Windows PC (FastAPI 백엔드)    │                 │      라즈베리파이 5 (실기기)       │
│                                 │                 │                                 │
│  [HardwareDeviceProvider]       │                 │  [pi/main.py (하드웨어 데몬)]    │
│    - GPIO를 직접 건드리지 않음!  │  HTTP Polling   │    - 1~2초마다 desired-state 조회│
│    - DB에 desired_state 저장    │ ◄─────────────► │    - gpiozero로 실제 LED/모터 제어│
│    - 파이의 보고를 DB/WS로 중계 │                 │    - POST /state 로 현재 상태 보고│
└─────────────────────────────────┘                 └─────────────────────────────────┘
```

### 1단계: 백엔드 `HardwareDeviceProvider` 작성 (`backend/iot/hardware_provider.py`)
- `base.py`의 `DeviceProvider`를 상속합니다.
- **절대 라즈베리파이 GPIO 라이브러리(`gpiozero`)를 백엔드에서 import하지 않습니다.** (백엔드는 PC에서 실행됨)
- 대시보드 제어 명령이 오면 DB의 `desired_state`를 갱신하는 중계 역할만 합니다.

### 2단계: 백엔드 모드 전환 (`backend/.env`)
```env
DEVICE_MODE=hardware
```

### 3단계: 라즈베리파이 데몬 작성 (`pi/main.py`)
- 라즈베리파이에서 실행되는 독립 프로세스입니다 (`backend`의 코드를 직접 import하지 않음).
- **라즈베리파이 5(RP1 칩셋) 주의사항**:
  - 기존 `RPi.GPIO`는 RP1 칩셋과 호환되지 않아 작동하지 않습니다. 반드시 `gpiozero`와 `lgpio`를 사용합니다.
  - PyPI에서 `pip install lgpio`를 시도하면 C 컴파일 에러가 발생하므로, 라즈베리파이 OS 기본 APT 패키지(`sudo apt install -y python3-gpiozero python3-lgpio`)를 설치하고 `python3 -m venv --system-site-packages venv`로 가상환경을 생성하여 상속받습니다.
  - 실기기 배선 후 데몬을 돌리기 전 `python test_hardware_gpio.py`로 1분 자가진단을 먼저 수행합니다.
- `gpiozero`와 `lgpio`를 사용하여 실제 핀을 제어합니다:
  - 혼잡도 안내 LED (Green: GPIO 17, Orange: GPIO 27, Red: GPIO 22 등)
  - 임산부석 압력센서 (GPIO 디지털 입력 또는 Button)
  - 배경 이동 모터 (릴레이 또는 모터 드라이버 GPIO 출력)
- 루프:
  ```python
  # 1. 백엔드 목표 상태 폴링
  res = requests.get(f"{BACKEND_URL}/api/v1/devices/led_congestion/desired-state")
  # 2. 실제 GPIO 핀 반영 (gpiozero)
  # 3. 반영 결과 보고
  requests.post(f"{BACKEND_URL}/api/v1/devices/led_congestion/state", json={"current_state": "on"}, headers={"X-Device-Api-Key": KEY})
  ```

## 7. AI 협업 시 절대 지켜야 할 3대 안전 원칙

   - `vision/` 가상환경 생성 시 `py -3.12 -m venv venv`를 사용하고, 폴더명은 `.gitignore`와 일치하도록 `venv`를 유지하세요.
   - `vision/main.py`의 **OpenCV DNN ONNX 구동 로직**을 PyTorch로 되돌리지 마세요. (Windows DLL 오류 및 수 GB 다운로드 원천 차단)
   - 웹캠 화면 한글 깨짐 방지를 위해 `pillow` 라이브러리를 활용하세요.
   - `frontend/hooks/useSubwaySocket.ts`의 WebSocket 재연결 인터페이스를 임의로 변경하지 마세요.
2. **외과적 변경 (Surgical Changes)**:
   - 새 기능을 추가할 때 전체 파일을 덮어쓰지 말고, 필요한 함수나 필드만 국소적으로 수정하세요.
3. **직접 실행 및 확인**:
   - AI가 코드를 제시하면 반드시 터미널에서 실행해보고, 대시보드 배지가 여전히 **초록색(● 실시간 연결됨)**인지 확인하세요.
